# Deduplication and Merge Rules

1. Read the existing target file before writing, when tools permit.
2. Prefer updating `daily/YYYY-MM-DD.md` over creating a second file for the same date.
3. Before adding an event, compare date, known time, participants/context, and event summary.
4. Merge duplicate descriptions into one entry; preserve additional unique detail.
5. Do not replace a full-day diary with a summary of only the latest window.
6. If only part of the conversation is available, keep `coverage: partial`.
7. Use timestamps only when present in source material or provided by a reliable clock tool.
8. Remove resolved items from continuity; preserve them in the diary if historically meaningful.
9. If the user corrects an entry, replace the inaccurate version and note the correction when useful.
10. If an operation fails, keep the proposed update separate from the saved file and report failure honestly.
